# ThinQ Real 사내 전환 검증(UAT) 체크리스트 — v1 (2026-09-21)

> **담당**: 협업자(UAT 담당 — 실사용 관리자) / **승인·지원**: 담당자(강원석 책임) / **작성**: 외부 트랙
> **목적**: 사내 컨테이너(QA 환경)가 현행 사이트(thinqreal.com)와 **똑같이 동작하는지** 실사용자 눈으로 끝까지 돌려보고, 다른 점을 찾아내는 것. 코드를 볼 필요 없고, 평소 관리자 페이지를 쓰듯 **누르고 → 기대와 같은지 적는** 일이다.
> **끝의 정의**: 아래 표의 모든 항목에 판정(○ 같음 / △ 다르지만 무해 / × 다름·오류)이 채워지고, △·× 항목이 "차이 보고 양식"으로 담당자에게 전달되면 끝.

## 0. 시작 전 준비 (협업자 혼자 — 이 표대로 하면 됨, 담당자 동행 불필요)

| # | 준비 | 방법 | 확인 |
|---|---|---|---|
| 0-1 | QA 주소 | `https://kic-qa-thinq-real.thinqcloud.link` — **사내망(사내 PC)에서만** 열림. 즐겨찾기 등록 | ☐ |
| 0-2 | SSO 로그인 + **캐시 주의** | 주소를 열면 사내 로그인 화면 → 본인 계정. 관리자 페이지 주소는 `…/thinqreal_admin.html`. **처음 열 때 반드시 Ctrl+F5(강력 새로고침)** — 예전에 열어본 적이 있으면 브라우저가 옛 페이지(구글 백엔드 호출본)를 보여줘서 코드 요청이 엉뚱한 곳으로 간다(9/22 실제 발생). 확실히 하려면 시크릿 창 사용 | ☐ |
| 0-3 | 관리자 인증 코드 | 관리자 페이지에서 이메일 인증 [코드 요청]을 **한 번만** 누른 뒤(QA는 메일이 실제로 오지 않음 — 60초가 지나 다시 누르면 **새 코드가 발급돼 먼저 본 코드는 무효**), **새 탭에서** `https://kic-qa-thinq-real.thinqcloud.link/api?type=auth_code_peek&kind=admin&email=본인메일` 을 열면 `"code":"123456"` 이 보인다 → 그 6자리를 입력. 메인 사이트 게이트(1-1)는 `kind=auth` 로 같은 방법. 토큰은 7일 유효. **"인증 코드가 일치하지 않습니다"가 나오면** 페이지를 거치지 말고 같은 탭 주소창에서 순서대로 ① `…/api?type=admin_auth_request&email=본인메일` → `ok:true`(60초 이내 재요청은 `cooldown`) ② peek 주소를 Ctrl+F5로 3번 열어 `code`가 매번 같은지 ③ `…/api?type=admin_auth_verify&email=본인메일&code=그6자리` → `ok:true`면 정상. 실패하면 JSON의 `error` 값(`code_mismatch`/`code_expired`/`too_many_attempts`)과 peek의 `pod`·`kv` 값을 담당자에게 그대로 전달. **담당자 통과(2026-09-22, 키트 v4.3)** — 주소창 경로·페이지 경로 모두 대시보드 진입 | ☑ |
| 0-0 | **선행 조건(담당자)** | 키트 v4.1(정적 파일 최신화 + API 자동 치환)이 QA에 배포돼 있어야 한다 — 그 전에는 QA 페이지가 **라이브 운영 백엔드를 호출**하므로 UAT 금지. **2026-09-22 QA 준비 완료 확인(담당자)** — 0.13.0, 치환·peek 실측 통과 | ☑ |
| 0-4 | 비교 기준 | 현행 사이트 `https://thinqreal.com` 관리자 페이지를 **옆 창에** 띄워 두고 화면·동작을 나란히 비교 | ☐ |
| 0-5 | 테스트 데이터 규칙 | 입력하는 이름·주제 앞에 **`[UAT]`** 를 붙인다 (예: `[UAT] 홍길동`). 검증이 끝나면 `[UAT]` 데이터는 전부 삭제 — QA 데이터는 남는다 | ☐ |
| 0-6 | 기록 | 이 문서를 인쇄하거나 복사해 판정·비고를 채운다. 화면 캡처는 사내 정책상 불가 → **문구를 그대로 옮겨 적기** | ☐ |
| 0-7 | (선택) 사내 Claude | 막히면 사내 Claude Code 새 채팅에 "브리핑과 UAT 체크리스트 기준으로 N-N 항목이 막혔어: (문구)" 라고 물으면 안내한다 | ☐ |

**QA에서는 안 되는 것(정상)**: 메일 실발송·텔레그램·캘린더 등록 — 전부 "억제"돼 있어서 화면상 완료돼도 실제 도착하지 않는다. 이것은 9단계(OP·SMTP 이후)에서 본다.

## 1주 계획 (2026-09-28 확정 — 구 3주 계획 폐기)

1~8단계는 총 57항목, 항목당 몇 분이라 **실작업 4~6시간**이다. 본업과 병행해 하루 1~2시간이면 5일에 끝난다. 순서는 데이터 의존 관계(1단계 예약 → 2단계 승인 → 5단계 설문) 그대로.
